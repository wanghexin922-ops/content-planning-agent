# 需求、范围与成功标准

## 用户和问题

内容运营需要在预算与截止时间内形成可执行的活动方案。一次检索或串行生成不能解决超预算、工具故障和重复执行：系统必须看见工具反馈、调整下一动作，并明确哪些工作已经完成。

## 范围

输入：主题、预算、截止时间，附带请求 ID、可调整的制作偏好和可选受众。资料：带 ID 的合成素材、费用和耗时表。输出：任务计划、步骤依赖、工具实际状态、脚本产物、费用、保存状态及未完成原因。

模型决策边界：可以选择素材和制作方式、重试失败动作、请求补充或停止；不允许改写用户预算和截止时间。业务阶段未真正执行，最终完成表示规划方案保存成功。

不在范围：真实内容平台、真实发布、完整营销创意质量评估、多人资源排期、UI、部署、多 Agent。题目允许本地/Mock 业务工具，因此脚本工具使用可追溯的事实模板。

## 验收映射

| 题目要求 | 成功标准 | 验证入口 |
|---|---|---|
| 正常完成 | 费用和时长满足约束；数据库存在方案；输出含完整计划 | normal |
| 缺预算或截止时间 | 不编造约束，返回 needs_input，列明缺失字段 | missing_info；两个单字段缺失单测 |
| 工具失败 | 失败记录保留；成功产物不丢失；模型观察错误再决策 | tool_failure；保存/模型错误单测 |
| 预算超限 | 观察不可行估算后选择替代方式并复核，或说明缺口 | over_budget、no_feasible_plan |
| 重复执行 | 相同请求只有一份方案，无新增工具调用 | repeated_request、数据库记录数检查 |
| 失败步骤续跑（加分） | 重启进程后保留成功脚本，从失败观察处继续 | test_resume_across_separate_processes |
| 执行上限 | 工具或模型轮数到顶时返回 incomplete_limit | step_limit；无函数调用轮数测试 |
| 至少两条决策路径 | 真实模型正常路径和超预算/故障路径的工具调用发生变化 | examples/live/normal、over_budget、tool_failure（已实际生成） |

以上用例的输入、实际输出、Trace 位于 `examples/mock/<case>/`；真实模型评估采用相同案例结构，但单独存放。

## 业务口径

- 预算为最多两位小数的非负模拟单位；采用 Decimal 计算，工具输出 JSON 数值。
- 费用为最终方案业务执行费用。规划中放弃的方案不计重复执行费用；模型 API 账单另行计算。
- 时间使用带时区 ISO 8601，按准备、脚本、制作、审核、发布串行相加。不承诺真实业务耗时。
- 相同 request_id 但参数不同明确冲突；修改预算或补全约束需要新 ID。
- 成功、失败、待输入、未完成、达到上限是不同状态，不能用笼统“完成”掩盖问题。

## 补充验收

真实模型覆盖 13 个场景，额外区分单独缺预算、单独缺截止时间和简历视频受众一致性。原始主题必须保持，缺少主题资料不能替换成其他产品的活动。

## 第3、4项增补

最新全量矩阵17例，在原有案例上增加时间紧张、费用变化、低预算素材选择和持续故障。关键三场景各重复三次。成功标准新增独立原始数据复算、必需阶段与依赖检查、引用与执行历史一致性，详见03与07文档。
