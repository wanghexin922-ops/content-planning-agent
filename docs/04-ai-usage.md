# AI 使用范围与个人贡献记录

## 开发方式

本项目由候选人确定题目、需求与实施范围，借助 Codex 完成代码、测试和文档，并接入 DeepSeek Flash 验证真实模型决策。个人累计投入约 **2.5 小时**，为本人回顾估算；AI 自动运行及等待时间不等同于个人持续操作时间。

## 个人参与与贡献

- **需求确认与选题**：提供完整考核要求，选择“内容任务规划 Agent”，多次要求对照题目检查验收覆盖和交付完整性。
- **模型接入与本地运行**：确定使用 `deepseek-flash`，亲自配置本地 API Key，并运行过项目命令。个人操作未单独留存逐条命令和结果，因此不把仓库内整套自动化验收归为本人逐项手工执行。
- **推动迭代**：要求检查不足和改进空间，确认先完成前两项优化，再推进后两项；要求增加真实例子验证，并关注自行测试的使用方式。
- **交付整理**：确认 Git 版本保存、公开仓库和源码附件等提交方式，要求完善 README 和材料说明。

个人参与重点在需求、接入、运行和迭代要求；核心代码及具体修复由 Codex 辅助实现，未声称为个人独立手写。本文根据实际协作过程及本人确认的信息整理。

## AI 辅助范围

Codex 辅助完成题目比较、技术方案、合成数据、Python 实现、模型适配、Mock、SQLite 状态管理、故障处理、测试、验收脚本与文档整理。没有使用子 Agent、多 Agent 或 LangGraph/ADK 等框架。

模型接入查阅了 DeepSeek 官方文档；用户在本地配置密钥后，由 Codex 执行真实模型验收并保存结果。密钥未写入提交仓库；只提供 `.env.example`。

## 改动与验证责任

| 工作 | 实施及验证方式 | 证据 |
|---|---|---|
| 保存前预算、截止时间和步骤依赖检查 | AI 辅助实现，并执行边界及错误输入测试 | [自动化测试](../examples/test-results.txt) |
| 请求防重复、任务锁和状态持久化 | AI 辅助实现，检查数据库唯一性与并发锁 | [设计说明](02-solution.md)、[测试](../tests/) |
| 超预算、缺信息和工具失败处理 | AI 执行离线及真实模型验收 | [评估报告](03-evaluation.md) |
| 失败终态续跑、保留成功产物与错误历史 | AI 执行失败、恢复、重复提交三个进程 | [真实续跑记录](../examples/live_resume/evaluation-summary.json) |
| 事实来源限制、独立复算、约束变化和重复试验 | 经候选人确认优化方向后，由 AI 实施并验收 | [优化 1、2](06-improvements.md)、[优化 3、4](07-replanning-evaluation.md) |

已保存的结果为 71 项自动化测试通过、离线 17/17、真实模型 17/17、关键场景三轮独立重复 9/9。以上是工具实际运行记录，个人运行经历与这些系统验收记录分开说明。Mock 仅验证流程，不能证明真实模型决策效果。

## 失败记录与修改结果

首轮真实验收曾出现无素材时模型改换用户主题的问题，结果为 12/13。Codex 根据 Trace 增加原始主题约束、补充测试并重新验收。后续又针对事实边界、失败续跑、持续故障终态归因和独立审计进行改进；原始失败记录保留在 `examples/history/`，没有覆盖成成功样本。

具体失败分析与最新结果见 [评估报告](03-evaluation.md)。这些修改由 AI 辅助实施，个人贡献在于提出核验与完善要求、确认推进顺序以及参与接入和运行。
